# Source Notes / Constraints for Course Design

## Зачем существует продукт

Нужно создать автономный онлайн-продукт, который требует минимального участия автора после публикации.

Покупатель должен:
1. сам найти курс;
2. сам оплатить;
3. автоматически получить доступ;
4. пройти курс в удобное время;
5. скачать нужные материалы.

Курс не должен зависеть от живых созвонов, обязательных домашних заданий, когорты или постоянного присутствия автора.

## Аудитория

Не абсолютные новички и не узкие AI-специалисты.

Главная аудитория:
- уже пробовала ChatGPT;
- что-то делает с помощью AI;
- понимает, что использует инструмент поверхностно;
- чувствует, что AI развивается быстрее, чем она успевает следить;
- хочет системно догнать рынок без изучения десятков сервисов.

## Принципы содержания

- практическая ценность важнее полноты;
- один урок = одна понятная задача или способность;
- показывать реальные workflows, а не перечислять кнопки;
- сначала результат и применение, потом теория;
- не превращать курс в энциклопедию функций;
- не раздувать количество материалов ради ощущения ценности;
- избегать долгих лекций;
- интерфейсно-зависимые части держать отдельными короткими уроками, чтобы их можно было быстро обновить;
- курс должен быть пригоден для самостоятельного прохождения;
- пользователь должен понимать, что делать после каждого урока.

## Формат записи

Можно чередовать три режима:
1. автор + презентация — когда нужна модель мира;
2. автор + интерфейс — когда показывается механика;
3. только интерфейс — когда важны конкретные действия.

Не делать обязательным сложный продакшн каждого урока.

## Коммерческие ограничения

- первый продукт должен быть массовым и понятным;
- не добавлять персональный менторинг;
- не добавлять live-сессии как обязательную часть;
- не строить комьюнити, тесты, сертификаты и геймификацию в MVP;
- не уходить глубоко в Codex, media, automation — это будущие отдельные продукты.

## Что skill должен сделать

Не придумывать новый продукт вместо существующего.

Нужно:
1. проверить текущую структуру через capability-based design;
2. найти реальные пробелы и дубли;
3. предложить изменения только там, где они улучшают способность ученика действовать;
4. сначала сделать один sample lesson;
5. не строить весь курс до утверждения sample lesson;
6. не добавлять факты о текущем ChatGPT без проверки источников;
7. явно маркировать места, где нужен свежий факт, интерфейсная проверка или внешний источник.
